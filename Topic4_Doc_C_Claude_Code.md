# Doc C · Discovery Pivot · Claude Code
## Mercury · Joe as Ashwin

**Open when:** "Claude Code" / "terminal agent" / "Anthropic" / "CLI-first"

---

## What Claude Code does well (say this first)

- Excellent **CLI-first agent** for terminal-native engineers
- Strong **multi-step autonomy** on complex refactors
- High leverage for **senior engineers** who live in the shell
- Anthropic model quality on long-horizon tasks
- Growing **enterprise controls** (permissions, hosting options)

**Say:** "Claude Code is excellent for terminal-native power users. I would not dismiss it."

---

## Where Mercury teams usually feel the gap

| Mercury moment | Claude Code gap | Cursor angle |
|----------------|-----------------|--------------|
| **~58 eng, mixed levels** | CLI-first excludes part of the org | VS Code-familiar IDE; broader adoption |
| **Ashwin's standardization mandate** | Power users adopt; squads diverge | One product standard for whole eng org |
| **Central integration** | Great for seniors running agents; harder to govern org-wide | Rules + admin controls for DevEx |
| **Visual review workflow** | Terminal diffs vs IDE review UX | Inline diffs, familiar PR flow before merge |
| **Model strategy** | Locked to Anthropic | Model agnostic: Claude, GPT, Gemini, Composer |

## Cursor differentiators vs Claude Code (talk track)

**30-second version:**
> "Claude Code is strong in the terminal for engineers who want a CLI-first agent. Cursor covers the full SDLC surface: visual diff review, tab completion, multi-model choice, and an IDE most of your org already knows from VS Code. For standardization across squads, not just power users, Cursor gives DevEx one governable standard."

**60-second version:**
> "We often see a two-layer pattern: terminal agents for a subset of seniors, and an IDE standard for the whole org. At Mercury's size, Ashwin's AI Enablement hire is about shared infrastructure, not more siloed experiments. Cursor lets you standardize models, Rules, and admin policy while still giving engineers access to Claude, GPT, or Composer inside one workspace. PayPal and Sentry talk about Cursor as org-wide scale, not individual heroics."

## Discovery questions (Claude Code-specific)

1. "Is Claude Code limited to a subset of senior engineers, or deployed broadly?"
2. "How does DevEx govern prompts, permissions, and what repos agents can touch?"
3. "Do less terminal-native engineers get value, or is adoption uneven?"
4. "When work spans multiple files in the monolith, are people in the terminal or the IDE?"
5. "Are you standardized on Anthropic models, or do teams want model choice?"
6. "What would 'good' look like for org-wide adoption, not just power users?"
